# StockLite v10.4-dev iPhone統合試験版

採用する暫定方式: ZXing 0.21.3で全体映像をPNGとして順次解析し、異なる映像フレームで有効な同一コードを連続2回、1秒以内の間隔で確認する。解析間隔は最短200ms。カメラ取得は実機試験で使ったhtml5-qrcode 2.3.8を維持し、その解析を一時停止してZXingで認識する。

これは在庫アプリ本体へ組み込んだ隔離試験版。診断版のFボタン、期待JAN入力、3秒カウントダウンはない。スキャン画面へ入ると読取を開始し、登録済みなら数量確認、未登録なら既存の品目登録へ進む。数量の変更は「確定」ボタンで保存する。

## 使用手順

1. 本番の設定画面でJSONバックアップを手動出力し、保管する。この作業では本番端末のバックアップ取得は実施していない。
2. ZIPのios-candidate内を、本番と異なるオリジンのHTTPS試験サイトへ配置。単なる同一GitHub Pagesの別パスや、同じユーザーの別リポジトリは通常オリジンが同じなので隔離にならない。本番のindex.htmlへ上書きしない。
3. 初回はオンラインでSafariから開き、ヘッダーのv10.4-dev表示を確認する。解析ライブラリは外部CDNから取得する。初回通信が失敗した場合は通信を確認し再起動するか、従来方式へ切り替える。
4. 空の試験データで登録・スキャン・数量確定を確認する。必要なら試験サイトだけに本番JSONのコピーを読み込む。本番データの編集結果とは独立しているため、試験用JSONを本番へ復元しない。
5. スキャン画面でコード全体と余白を映像内に入れる。iPhoneはZXing全体映像が既定。読み取り方式で「従来方式」を選ぶとv9 html5-qrcodeへ戻せる。端末の保存データ形式は変わらない。
6. PWAは試験サイトをホーム画面へ追加して動作を確認する。サイトデータを消す必要はない。

## 実装・保護

- 基準ソースはGit履歴上のv9 BUILDを持つ55131b3。v9 ZIPとのバイト一致は未確認。
- iPhone分岐だけを新方式へ接続。Androidのスキャナ分岐はv9と同一。
- JAN-8/JAN-13は形式、桁数、チェックデジットを検査。QRはZXingの形式情報に基づいて受け付け、JANチェックをしない。
- 数量確認・購入・使用・品目登録・バックアップ・復元・IndexedDBの関数はv9と同一。DBはstocklite v1 / state / data。初期化やマイグレーションを追加していない。
- 数量確認中は追加の画像解析を休止。同じコードが映り続ける場合の再通知を抑え、読取不可4フレームまたは別コードへの移行で再読取できる。1800msの既存重複抑制も維持。
- 解析は常に1件ずつ。停止時は遅延結果を破棄し、再起動時は前の解析の終了を待つ。画面非表示・pagehideでiPhoneカメラも停止。
- 試験用SWはstocklite-ios-candidateプレフィックスのキャッシュだけを整理する。本番キャッシュは削除しない。外部CDNライブラリのオフライン利用は保証しない。
- 認識コード・カメラ画像を診断ログとして保存しない。品目のコードと在庫履歴は既存アプリ機能として保存される。
- ios-fullframe.jsの内容はindex.html内にも埋め込み済み。実行時に別JSの配置を忘れて起動できなくなる問題を避ける。

## 検証済みと未確認

Node模擬試験: 合格。v9のデータ操作関数/Android分岐の同一性、JAN-8/JAN-13チェック、QR受付、2回一致から数量確認への接続、確定前に在庫が変わらないこと、購入/使用の確定、保存失敗時の巻き戻し、同一コードの二重通知抑制、停止後の遅延結果破棄、従来方式への切り替えを確認。開発環境では `node verify.cjs`。

構文チェック: 合格。

実機の根拠は診断版FのJAN-13試験。直近のv10.2ログは19回中18回一致、1回タイムアウト、不一致0。この統合版そのもののiPhone動作、JAN-8/QR、Android回帰、実IndexedDBの保存/再起動、権限拒否・復帰、PWA、長時間の負荷・発熱は未確認。模擬試験を実機確認と混同しない。

## 必要な受入確認

Safariとホーム画面PWAでJAN-13/JAN-8/QRを確認。登録済みの購入・使用は確定前に在庫不変、確定後に1回だけ保存されること。未登録コードは登録画面へ進むこと。読取途中の画面切替、数量確認のキャンセル、権限拒否・復帰、再起動後の保存状態を確認。Androidは既存速度と全機能の回帰を確認する。

初回認識速度はv10.3診断版の統一手順で別途比較する。本体では操作者がコードを映像へ入れた瞬間を自動計測しない。速度目標の達成は未確定。

## 変更と切り戻し

追加ディレクトリios-candidateのみ。本番ルートのindex.html/sw.js/manifestは変更していない。mainへの反映・GitHubへのpush・試験サイト公開は行っていない。

問題時はiPhoneの読み取り方式を「従来方式」へ変更するか、試験サイトを閉じて既存本番を使用する。本番データ消去は不要。正式反映は統合版の実機検証と承認の後に行う。
